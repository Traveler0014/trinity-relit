# Ranch 重写：仍需原版映射或状态支持的部分

2026-10-09。本轮遵守「原有 26 个房间 ID 不变」的范围。`ranch.js` 中 26 个房间的默认英文描述从各自房间对象属性 50 指向的动作例程重组；门的默认开关来自原版对象属性。无法逐字落实或无法接到当前状态 API 的片段没有猜写。中文紧随英文。

## 房间集合与跨章出口

原版还有 **Front Deck（对象 #6）**。它不在现有 26 个 ID 中。真值表里有九条从现有房间通向它的出口：`front_yard` 的 `w/u/in`、`assembly_room.e`、`se_room.e`、`ne_yard` 的 `s/u`、`se_yard` 的 `n/u`。这些出口没有指向别的房间来凑数；是否增加 `front_deck` 由用户决定。其房间动作例程在原版地址 `0x28588`，可据此逐字重建描述。

另有 **28 条**出口进入 Desert / Foothills 的同名通配房间。`CHAPTER_PLAN.md` 尚未给这些房间的对象号与实现 ID 建立一一映射，因此没有猜目标。`nw_ranch.n` 暂保留到 `behind_shed` 的现有返程桥；原版该方向指向 Foothills #225。`nw_ranch.nw` 确认直达 Shallow Crater #456，已接入。Desert 进入 Ranch 的 `behind_shed.s` 未修改。

`scripts/verify_exits_static.py` 将目标对象号没有实现 ID 的出口计入「无法比对」，并在 JSON 明细的「未映射目标」中列出。当前 Ranch **83 条已映射可通行出口一致、0 缺失、0 目标错误、0 凭空；7 条条件出口和 37 条未映射目标单列**。显示的 100% 仅是 83 条可比出口的一致率，不能解释为原版 Ranch 地图全部还原。

## 原版条件与当前状态的差异

- 壁橱门的开关有现成的 `closet_door_closed` 标志，`closet` 和 `assembly_room` 的描述已按原版分支切换。其他门的原版开关属性没有对应的当前状态标志，描述使用原版初始状态的文字；门的开关行为仍需独立建模。
- 厨房原版橱柜里起初有一把牛排刀。当前 `items.js` 的 `knife.start` 是 `null`，也没有橱柜容器。本轮没有改物品系统；描述只在 `itemAt("knife") === "cupboard"` 时使用原版的单物品片段。当前默认显示的是原版橱柜空时的分支。
- 风车下的描述会随望远镜破损属性变化。本轮按 `binoculars_broken` 标志重组两个原版片段，但当前游戏还没有设置此标志的事件；默认显示原版未破损分支。
- Underwater 的原版可见描述由照明条件控制。当前引擎没有完整的水下光照状态，故显示已核对的有灯笼分支；未为无光状态编造英文。
- 蓄水池、潜水和爬风车的条件出口涉及原版独立动作、气息与物品状态。为保证既有 26 房间在当前引擎可达，只保留了目标明确的可通行方向；这些条件的完整机制尚未还原。静态校验把原版的 7 条条件出口单列。

原版 `.DAT`、反汇编文本和派生真值文件均只在本地使用，不随本文件提交。
