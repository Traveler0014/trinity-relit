# 自然语言指令识别实施计划

## 目标与边界

玩家用同义表达描述动作时，不再依赖穷举所有表达。parser 保留即时命令入口；未精确识别的动作由模型从当前场景的候选标准命令中选取。原版规则仍决定条件、效果、文本与回合。

当前采用浏览器本地量化嵌入模型，保持静态部署；按中文/英文分别懒加载 bge-small-zh-v1.5 / bge-small-en-v1.5。模型权重约 24/34 MB，还需 tokenizer 和 WASM 运行时；不能称总下载量为 24 MB。语义提供方使用独立接口，未来可替换远程 API，密钥不可进入前端。

## 分阶段清单

- [x] 1. 候选命令层：当前房间有 match 的事件、眼前/随身物品、出口；过滤 when 与事件优先级；排除旧的仅 triggers 入口。
- [x] 2. 执行层：parser 精确匹配优先；目标未解析时允许模型介入；模型不能返回脚本/剧情/状态，只返回本次候选 ID。
- [x] 3. 原版互动：补入已由 dfrotz 核实的帮助老妇人、操作她手中雨伞响应，解决模型无合法动作可选的问题。
- [x] 4. 模型与 UX：首次需要时在 Worker 加载，进度、取消、失败可恢复；候选向量批处理缓存；不阻塞首屏；拒识与歧义不执行。首版模型结果均由玩家确认后才执行。
- [x] 5. 生命周期：推理和确认期间不暂增回合；超时/错误/取消不计回合；执行前重验状态与条件；拒绝并发输入；UI finally 解锁。
- [x] 6. 评测：确定性测试覆盖纸鸟、老妇人、树上雨伞、日晷、否定/询问/歧义、假 ID、状态过期、超时与导出；真实模型独立评测自然表达和拒识，记录实测。
- [x] 7. 验收：verify、npm test、出口不新增偏差、浏览器首屏与推理交互截图/console；原版及派生数据不提交；文档记录仍有的限制。

## 验收原则

相似度不是概率。首版确认步骤不计回合，仅最终动作执行一次。需要拿不到的对象时，仍执行正常的失败响应，不能改猜另一件东西。候选标签只描述动作，不包含动作结果或原版故事正文。离线且模型未缓存、下载被阻断时仍可用标准命令。

## 同源资源准备

`npm run prepare:models` 固定模型仓库 commit 与推理库版本，将模型、运行时与许可证放入 Git 忽略的 `prototype/vendor/intent/`；Pages 部署上传前准备这些文件。官方源不可达时可显式指定 `--model-host https://hf-mirror.com`。首屏不读取这些资源，仅需要语义识别时按语言读取。未准备资源时尝试公共源；失败可取消或改用标准命令。

## 2026-10-12 失败可诊断与下载稳健性

背景：试玩反馈“模型加载失败时重试也无法恢复，也没有报错码可以辅助排查”。对 PR #4/#5 的现有实现做了不改变产品行为的加固，只碰 worker / resolver / 进度呈现与接线，不动 `engine.js`。

- **失败带阶段**：worker 随错误回传 `stage`（`runtime` / `download` / `initializing` / `infer`）与原始 `message`；resolver 把它附成带 `stage` 的错误，并通过 `onFailure` 上报诊断通道；Worker 自身起不来（脚本/资源/线程级）固定归为 `worker`，不再退化成无阶段的“模型不可用”。`main.js` 把它写进调试面板（默认不可见）：「语义识别失败：stage=download message=Failed to fetch」。
- **不把库的异常升级成 Worker 死亡**：库内部未处理的 rejection 会被浏览器报成 Worker 级 error 事件，而 `onerror` 会 `dispose()`——既丢掉已捕获的失败阶段，也把正在进行的模型下载一并作废（与 PR #4 “超时保留下载” 的目标相冲）。现在 `unhandledrejection` 被拦下转交调试通道，不影响待决请求。
- **运行时镜像回退**：远程模式按 `huggingface.co → hf-mirror.com` 顺序尝试，失败即切换并提示“模型源站不可用，正在切换镜像下载…”，切过的镜像本次会话优先；vendor 同源模式不受影响。本机实测对 HF 吞吐 0.15–2.6 MB/s（同一 24MB 文件 12–156s），源站不可达是主要失败原因。
- **进度呈现**：百分比仍不展示（保持 PR #5 结论），但补上文件名（分词器 / 模型配置 / 模型权重）与阶段，如“正在下载中文识别资源：模型权重 · 已接收 12.3 MB”。`initializing` 改由 onnx 权重的 `done` 分界触发（“资源已接收，正在初始化语言模型（首次较慢）…”），不再让每个小文件的 `done` 都改写状态再被下一个文件覆盖（闪烁）。已就绪的模型直接进识别，热请求不再多闪一条“正在复用……”。
- **事实补充**：`tokenizer.json` 最终响应是 gzip 且没有 Content-Length，`config.json` 是 716B 且长度正确，onnx 在我这侧带完整长度。库的 `readResponse` 在 `newLoaded > total` 时把 `total` 顶成当前 `loaded`，所以**长度缺失或只是压缩长度**都会把百分比提前钉在 100%——两种触发方式等价，结论（不展示百分比、以 done/recognizing 为准）不变。
- 验收：`npm test` 63/63（新增 3 项：阶段与原始信息回传、Worker 级失败归类、调试通道不动待决请求；另加“用户取消不算失败”）；`npm run verify` 通过。浏览器实测：冷启动进度依次为首次准备 → 下载（带文件名与已接收 MB）→ 资源已接收正在初始化 → 正在理解你的意思，无假 100%；把远程源临时指向不可达域名时出现镜像切换提示，且调试面板收到 `stage=download message=Failed to fetch`。

## 2026-10-12 同意流程、设置层与取消语义（默认行为变更）

这是本次改动里**唯一改变默认行为**的一处：在此之前，首次未识别的自然语言会直接开始下载 24–34 MB 模型。

- **设置层**（新增 `settings.js`）：设备级偏好存 `trinity-relit:settings:v1`，与存档分开（导入别人存档不改本机开关）；`semantic: ask|on|off`，默认 `ask`；`get/set/subscribe` 供将来的设置面板消费。无 localStorage 时降级为仅内存生效。
- **征求同意**：`ask` 下首次需要时先弹说明（本地运行、不上传、约 25–35 MB、低配设备体验不佳；非安全源额外提示无法缓存），同意写 `on` 才开始下载，拒绝写 `off`。引擎的进度面板在接线后让位给决策层，避免征求弹窗与下载面板叠在一起。
- **取消语义**：进度面板上的「取消识别」在模型未就绪时＝不想在本地运行模型 → 停止下载、写回 `off` 并提示；模型已就绪时只放弃当次请求，不丢已加载的模型。引擎超时（`abort('timeout')`）不改设置、不销毁 Worker。
- **关闭与重开**：「更多」菜单在 `on` 态提供关闭语义识别（释放模型与运行时内存）与重试，在 `ask`/`off` 态就是征求弹窗；启用后仅在游戏状态未改变时重试上一条未判定输入；过期同意窗口不自动重放。
- **归属**：同意流程、取消语义、失败归因三层都在 `intent-notice.js`；引擎与 UI 都不直接读写设置，将来设置面板是同一份设置的另一个入口。
- 验收：`npm test` 77/77（新增同意/拒绝/关闭/下载中取消/就绪后取消/超时不改设置/菜单态/启用后重跑共 12 项）、`npm run verify` 通过；浏览器实测：先征求→拒绝（`off` + 「语义识别已关闭 · 更多」）→从「更多」启用→自动重跑→初始化阶段→候选确认执行。
